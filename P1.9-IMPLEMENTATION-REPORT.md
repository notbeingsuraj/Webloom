# Webloom P1.9 Implementation Report

## 1. Verdict

**GOOGLE REPUTATION EXTRACTION IMPLEMENTED**

Webloom can now recover Google Maps ratings and reviews through a source-grounded pipeline:
1. **Structured provider extraction** (Geoapify/Google Places record with `rating`, `userRatingCount`, `user_ratings_total`, `reviews`)
2. **Deterministic source-text parsing** (Google Maps page text like `4.1` + `82 reviews`)
3. **AI evidence-grounded extraction** (AI receives actual evidence, cannot guess/fabricate)
4. **Honest `unavailable`** when no evidence is retrievable

The core rule is enforced end-to-end: **AI never guesses a rating, never estimates a review count, never invents reviews.**

## 2. Reproduced Failure

The original symptom: Google Maps visibly shows `4.1` (rating) and `82 reviews` for Manan Furnitures, but Webloom displayed `rating: —` and `reviews: —`.

**Real reproduction via `/api/business/analyze`** (this session, live server):

```
URL:      https://www.google.com/maps/place/Manan+Furnitures/@29.9165,73.8789,17z/...
success:  true
name:     Manan Furnitures
category: Furniture Store
reputation: {
  rating: null, reviewCount: null, reviews: [], ...
  status: "unavailable"
}
```

Root-cause of the reproduction: the live Google Maps page fetch returned **no rating/review evidence** (Google does not serve structured rating data to the fetcher's user-agent; web-extraction returned `empty_result`, Geoapify returned `success` but its place-details response contains no `ratings` for this place). P1.9 correctly returned `null`/`unavailable` rather than fabricating — that is the desired honest behavior.

## 3. Current Reputation Data Flow

Before P1.9, the pipeline was:

```
Google Maps URL
  → GoogleMapsUrlParserProvider (URL identifiers only — no rating/reviews)
  → GeoapifyProvider.search/enrich  (ratings omitted for this place)
  → WebExtractionProvider            (business data only; reputation dropped)
  → BusinessResearchService._profileToIntelligence
      { rating: profile.get('ratings.rating'),     // null in practice
        reviewCount: profile.get('ratings.review_count'),
        reviews: [] }                              // always empty
  → CanonicalBusinessProfileService (reputation.rating/reviewCount/reviews)
  → /api/business/analyze|research → frontend "—"
```

The `BusinessProfile` model had `ratings.rating` and `ratings.review_count` but **no `reviews`, `review_summary`, `sentiment`, or `themes`** slots. `_profileToIntelligence` hardcoded `reviews: []`. No extraction stage populated reputation from Google Maps source evidence.

## 4. Root Cause

1. **No extraction stage for reputation evidence** — the P1.8 source-grounded fallback recovered address/phone/email/website/coordinates/name/category, but the contract (`extractFallbackFields`) had no rating/review handling.
2. **No field slots for reviews / summary / sentiment / themes** in `BusinessProfile`.
3. **`_profileToIntelligence` hardcoded `reviews: []`** and never surfaced `reviewSummary`/`sentiment`/`themes`.
4. **Provider records rarely carry ratings** (Geoapify's geocode/place-details endpoints return them inconsistently), and no deterministic page-text parser existed to recover `4.1` / `82 reviews` from retrieved source content.
5. **No identity-safety gate** for reputation data — a wrong-city provider record (e.g. Tarn Taran religious site) could have supplied its ratings.

## 5. Structured Provider Extraction

New `/services/GoogleMapsReputationExtractor.js` → `extractFromStructuredProvider()`:

- Reads rating from: `ratings.rating`, `rating`, `googleRating`, `userRating`
- Reads review count from: `ratings.review_count`, `user_ratings_total`, `userRatingCount`, `reviewCount`, `reviews` (numeric), `totalReviews`
- Reads reviews array from: `ratings.reviews`, `reviews`, `reputation.reviews`
- Maps Google Places aliases: `authorName` → author, `publishTime`/`relativeTimeDescription` → publishedAt
- Deterministic validation before acceptance; response `status: "source_extracted"`, `provenance: "observed"`

**Structured extraction result (verified in tests):**

```json
{
  "rating": 4.1,
  "reviewCount": 82,
  "reviews": [{"rating":5,"text":"Great furniture store...","author":"Rahul",...}],
  "status": "source_extracted",
  "provenance": "observed",
  "confidence": 0.9,
  "source": "provider_record"
}
```

## 6. AI Evidence Extraction

New `extractReputationWithAI()` — the AI **must** return evidence snippets for every value and a strict schema. Validation gates:

- rating: numeric, 1.0–5.0, explicit evidence snippet required, confidence ≥ 0.6
- reviewCount: integer ≥ 0, explicit evidence snippet required
- reviews: require at least text/rating/author with evidence; never accepted without evidence
- reviewSummary: grounded, with evidence

**Prompt rules enforced:** never guess a rating; never estimate a review count; never calculate an average from visible reviews; never treat sample size as total; never invent text/authors/dates; never merge another business's data.

**Verified in tests 12–24, 43–44:** AI extracts only from explicit evidence; AI returns null without evidence; AI cannot estimate; AI provenance stays `ai_generated`; no AI call when structured data is authoritative or no evidence exists.

## 7. Rating Validation

`validateRating(value)` — deterministic:

| Input | Result |
|-------|--------|
| 4.1, 3.5, 5.0, 1.0 | valid (rounded to 1 decimal) |
| 0.5, 5.5, -1 | rejected (`out_of_range` / `negative`) |
| `"4.1"`, `"3.7"` | accepted (parsed numeric) |
| 82 | rejected as rating (out of 1.0–5.0 range) |
| null | rejected |

If absent → `reputation.rating = null` (never `0`, never a fake default).

## 8. Review Count Validation

`validateReviewCount(value)` — deterministic:

| Input | Result |
|-------|--------|
| 82, `"1,200"`, 0 | valid (integer ≥ 0) |
| 4.5, -5 | rejected (`non_integer` / `negative`) |
| null | rejected |

Handle source labels: `82 reviews`, `82 Google reviews`, `82 ratings`, `userRatingCount`, `user_ratings_total`. Never confuse review count with sample size, photo count, search-result count, postal code, or rating. When only individual reviews exist (no total), `reviewCount` stays `null` and samples are preserved.

## 9. Review Extraction

`validateReview(review)` — each review preserves: rating, text, author, publishedAt, source, sourceUrl, provenance, confidence, verified. Google Places aliases (`authorName`, `publishTime`, `relativeTimeDescription`) mapped compatibly. Reviews without any meaningful content and without evidence are dropped. If no review text is available → `reviews: []`, no synthetic text.

## 10. Review Intelligence

New `/services/ReputationIntelligenceService.js` → `generateReviewIntelligence()`:

- **Only after raw extraction succeeds**; with zero reviews → `generated: false`, no sentiment/themes
- Deterministic sentiment aggregation + theme extraction from actual review text
- Optional AI summary with strict grounding rules
- Required distinction preserved: `reviewCount` (82) vs `reviewsAnalyzed` (5) vs `limitations` (`"Summary based on 5 returned review samples, not all 82 reviews."`)

## 11. Identity Safety

Reputation evidence is gated before accept:

- **City/state/postal/coordinates/provider-ID conflicts** rejected via existing `detectConflicts()` (0.35° ≈ 39 km coordinate threshold)
- Wrong-city records (e.g. Tarn Taran religious site vs Sri Ganganagar furniture store) are rejected entirely — their ratings must not merge
- **Regression tests 36 & 39** assert Manan Furnitures (Sri Ganganagar) accepts 4.1/82 and rejects Tarn Taran reputation data
- AI cannot resolve these conflicts — deterministic rejection only

## 12. Provenance

Every reputation field carries field-level provenance through all layers:

| Path | provenance | extractionMethod |
|------|-----------|-----------------|
| Structured Google source | `observed` | `provider` |
| Deterministic page-text parse | `observed` | `parser` |
| AI evidence extraction | `ai_generated` | `ai_evidence_extraction` |

- AI provenance is **never upgraded** to verified/observed (test 53: canonical keeps `ai_generated`)
- Provenance survives `BusinessProfile.set` → `_profileToIntelligence` → canonical projection → API response (tests 21, 22, 52, 53)

## 18. Known Limitations

1. **Live Google Maps page fetch often returns no structured rating** — Google serves rating/review data via JS-rendered payloads not available to the fetcher's user-agent. The pipeline is ready to consume structured provider data (Google Places API key, Geoapify ratings) when present; until then reputation honestly shows `unavailable`.
2. **Google Places API integration** (spec §4) requires a verified Place ID + API key. The extractor's Google-Places field mapping (`id`, `displayName`, `rating`, `userRatingCount`, `reviews`, `googleMapsUri`, explicit field-mask style) is implemented and tested, but no Places API credentials are configured in this environment — no fake success is reported.
3. **Review samples vs total:** Google/Geoapify return only a sample of reviews. The system preserves `reviewCount` (total) separately from `reviews` (samples) and states the distinction in review intelligence limitations.
4. **Review intelligence AI enhancement** is optional (deterministic baseline always available); no AI summary when no reviews are supplied.
5. Provider-record ratings merged only when the record passes the identity gate; a wrong-city provider (Tarn Taran) is rejected.
