# Plan 02-04: Design a Central AI Orchestrator

## Objective
Implement a provider-independent AI orchestration layer.

**Architecture:**
```
AIOrchestrator
  |
  |-- ModelRegistry
  |-- ProviderRegistry
  |-- CapabilityRouter
  |-- ProviderHealthMonitor
  |-- QuotaManager
  |-- CircuitBreaker
  |-- RetryController
  |-- OutputValidator
  |-- CostTracker
  |-- AIExecutionLogger
  |-- FallbackController
```

The application should request **capabilities** rather than hardcoding provider names.

**Example capabilities:**
- `business_extraction`
- `business_research`
- `entity_resolution`
- `review_analysis`
- `sentiment_classification`
- `competitor_analysis`
- `trend_classification`
- `report_generation`
- `structured_output`

Each capability should have its own model selection policy.

**Example policies:**
```
business_extraction:
  primary: efficient extraction model
  secondary: independent backup
  tertiary: reasoning model
  fallback: deterministic extraction

business_research:
  primary: Nemotron 3 Ultra, if available and suitable
  secondary: another high-quality reasoning model
  fallback: partial evidence-based result

review_analysis:
  primary: efficient classification model
  secondary: independent classification model
  fallback: mark analysis pending

report_generation:
  primary: high-quality synthesis model
  secondary: alternative synthesis model
  fallback: deterministic report template
```

These are example policies, not instructions to hardcode model names. Policies should be configurable.

## Tasks

### Task 1: Create ModelRegistry
- File: `apps/api/src/ai/ModelRegistry.js`
- Register models with metadata: id, provider, capabilities[], costPer1MTokens, contextLength, supportsStructuredOutput, supportsToolCalling, maxOutputTokens, qualityScores{}
- Methods: `register()`, `get()`, `list()`, `getByCapability()`, `updateQualityScore()`
- Load from config file or registry JSON

### Task 2: Create ProviderRegistry
- File: `apps/api/src/ai/ProviderRegistry.js`
- Register providers with: name, adapter, models[], healthCheck(), isConfigured(), getCapabilities()
- Methods: `register()`, `get()`, `list()`, `getHealthy()`, `getByCapability()`
- Integrate with existing provider adapters (OpenRouter, Gemini, Local, etc.)

### Task 3: Create CapabilityRouter
- File: `apps/api/src/ai/CapabilityRouter.js`
- Map capability → model selection policy
- Policy schema: primary, secondary, tertiary, fallback (each with modelId or capability criteria)
- Methods: `route(capability, context)` → returns ordered list of (provider, model) pairs
- Context-aware routing: consider task complexity, cost budget, latency requirements

### Task 4: Create ProviderHealthMonitor
- File: `apps/api/src/ai/ProviderHealthMonitor.js`
- Track per-provider: consecutiveFailures, lastSuccess, lastFailure, latency, errorRate, cooldownUntil
- Methods: `recordSuccess()`, `recordFailure()`, `isHealthy()`, `getCooldown()`, `getStats()`
- Integrate with existing AIHealthService
- Support Redis/shared state for serverless (Vercel) deployments

### Task 5: Create QuotaManager
- File: `apps/api/src/ai/QuotaManager.js`
- Track per-provider: monthlyBudget, currentUsage, dailyUsage, requestCount
- Methods: `canAfford(provider, estimatedTokens)`, `recordUsage(provider, tokens)`, `getRemainingBudget()`
- Support configurable monthly spending limits
- Alert when approaching limits
- Allow paid providers to be disabled entirely

### Task 6: Create CircuitBreaker
- File: `apps/api/src/ai/CircuitBreaker.js`
- States: CLOSED (normal), OPEN (failing), HALF_OPEN (testing recovery)
- Config: failureThreshold, successThreshold, timeout
- Methods: `execute(operation)`, `getState()`, `reset()`
- Per-provider circuit breakers
- Prevent fallback loops

### Task 7: Create RetryController
- File: `apps/api/src/ai/RetryController.js`
- Implement exponential backoff with jitter
- Provider-specific cooldown periods
- Respect Retry-After headers
- Bounded retries (maxAttempts)
- Methods: `executeWithRetry(operation, options)`

### Task 8: Create OutputValidator
- File: `apps/api/src/ai/OutputValidator.js`
- Validate structured output against JSON Schema
- For models without native structured output: implement JSON extraction, parsing, repair
- Schema validation with detailed error reporting
- Methods: `validate(output, schema)`, `repair(output, schema)`

### Task 9: Create CostTracker
- File: `apps/api/src/ai/CostTracker.js`
- Track per-request: provider, model, promptTokens, completionTokens, totalTokens, estimatedCost
- Aggregate: daily, monthly, per-capability, per-provider
- Methods: `record()`, `getSummary()`, `getProjection()`
- Integrate with QuotaManager

### Task 10: Create AIExecutionLogger
- File: `apps/api/src/ai/AIExecutionLogger.js`
- Structured logging for every AI request
- Log: requestId, capability, provider, model, latency, tokens, cost, success, error, fallbackCount, attemptDetails
- Support configurable log levels
- Integration with existing telemetry in AIService

### Task 11: Create FallbackController
- File: `apps/api/src/ai/FallbackController.js`
- Coordinate fallback selection when primary fails
- Prevent fallback loops (max fallback depth)
- Select next best provider based on capability, health, cost
- Methods: `selectFallback(failedProvider, capability, context)`, `recordFallback()`

### Task 12: Create AIOrchestrator Main Class
- File: `apps/api/src/ai/AIOrchestrator.js`
- Compose all components
- Main method: `execute(capability, input, options)` → returns standardized result
- Options: maxCost, maxLatency, requireStructuredOutput, evidenceText, groundingMode
- Handle provider chain execution with all resilience features
- Return result with full provenance (provider, model, tokens, cost, latency, fallbackCount, attempts)

### Task 13: Create Configuration
- Update `apps/api/src/config/env.js` with orchestrator config:
  - Capability policies (primary/secondary/tertiary/fallback per capability)
  - Monthly spending limits
  - Circuit breaker thresholds
  - Retry/cooldown settings
  - Cost tracking enabled
  - Health check intervals

### Task 14: Create Integration Tests
- Test orchestrator with mocked providers
- Test capability routing
- Test fallback behavior
- Test circuit breaker states
- Test quota enforcement
- Test cost tracking

### Task 15: Update AI Service Integration
- Modify `apps/api/src/services/AIService.js` to use AIOrchestrator
- Maintain backward compatibility for existing callers
- Deprecate old provider chain in favor of orchestrator
- Update `apps/api/src/ai/index.js` to export AIOrchestrator
