# Plan 02-01: Complete Existing Infrastructure Audit

## Objective
Inspect the entire repository. Locate and inspect:
- AI provider adapters
- Provider configuration
- Existing AI gateway integrations
- OmniRoute integrations
- OpenRouter integrations
- Gemini integrations
- Model identifiers and base URLs
- AI orchestration and routing logic
- Environment variable handling
- Health-check endpoints
- Retry and timeout logic
- BusinessResearchService
- BusinessDataExtractor
- DigitalAuditService
- LandingPageSpecService
- WebsiteStrategyService
- Every other AI-dependent service

Trace real requests from application entry points to the actual provider response.

Identify:
- Broken adapters
- Invalid model identifiers
- Invalid endpoints
- Authentication failures
- Unsupported request formats
- Incorrect response parsing
- Missing environment variables
- Quota exhaustion
- Rate limits
- Provider outages
- Unnecessary gateway dependencies
- Duplicate implementations
- Incorrect error handling
- Silent failures

Create a provider failure matrix with verified evidence.

Do not expose API keys or secrets.

## Tasks

### Task 1: Audit AI Provider Adapters and Base Classes
- Read and analyze `apps/api/src/ai/providers/` directory
- Document `AIModelProvider` base class interface
- Document `OpenAICompatibleProvider` implementation
- Document `OpenRouterProvider`, `GeminiProvider`, `LocalProvider`, `WebloomFineTunedModelProvider`, `BaselineProvider`, `FallbackProvider`
- Check `ExternalLLMProvider` wrapper around AIService

### Task 2: Audit Provider Configuration and Environment Variables
- Read `apps/api/src/config/env.js` AI configuration section
