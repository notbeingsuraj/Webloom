# Plan 02-10: Testing

## Objective
Comprehensive testing of the AI infrastructure covering all failure scenarios, adapter independence, and integration.

**Failure Scenarios to Test:**
1. All providers unavailable
2. Primary provider returns 429 (rate limited)
3. Primary provider returns 503 (unavailable)
4. Invalid credentials (401/403)
5. Invalid model identifier (404)
6. Incorrect endpoint
7. Provider timeout
8. Malformed JSON response
9. Incomplete model output
10. Fallback provider succeeds
11. All providers fail
12. Provider recovers after cooldown
13. Concurrent requests during outage
14. Quota exhaustion (402)
15. Deterministic fallback activates
16. Verified data unchanged after AI failure

**Constraints:**
- Test every adapter independently
- Add integration tests for actual provider endpoints only when credentials configured
- Don't make entire test suite depend on live API availability

## Tasks

### Task 1: Create Test Infrastructure
- File: `apps/api/test_ai_infrastructure_failure_scenarios.js`
- Mock HTTP server (using `nock` or `msw`) for provider simulation
- Test utilities: `createMockProvider()`, `simulateError()`, `simulateLatency()`, `simulatePartialResponse()`
- Shared test fixtures for each failure scenario
- Test runner with configurable live/mock mode

### Task 2: Test Provider Adapters Independently
- File: `apps/api/test_provider_adapters.js`
- For each provider (NVIDIA, HuggingFace, DeepSeek, Gemini, OpenRouter, Local, SelfHosted):
  - `healthCheck()`: configured/unconfigured, reachable/unreachable, auth success/failure
  - `generate()`: success, 400, 401, 404, 429, 500, 503, timeout, malformed JSON, empty response
  - `getModels()`: success, error
  - `getCapabilities()`: returns correct capability list
  - `classifyError()`: maps provider errors to standard taxonomy
  - `getUsage()`: returns usage stats
  - `validateConfiguration()`: detects missing config
- Mock all HTTP calls - no live API required

### Task 3: Test Orchestrator Resilience
- File: `apps/api/test_orchestrator_resilience.js`
- Test AIOrchestrator `execute()` with mocked providers
- Scenario: All providers unavailable → returns ALL_PROVIDERS_FAILED error
- Scenario: Primary 429 → fallback to secondary → success
- Scenario: Primary 503 → fallback to secondary → success
- Scenario: Primary 401 → disable primary → fallback to secondary
- Scenario: Primary 404 (model) → config error → fallback
- Scenario: Primary timeout → fallback succeeds
- Scenario: Primary malformed JSON → fallback succeeds
- Scenario: Primary incomplete output → fallback succeeds
- Scenario: Fallback succeeds after primary failure
- Scenario: All providers fail → deterministic fallback or error
- Scenario: Provider recovers after cooldown → selected again
- Scenario: Concurrent requests during outage → no race conditions
- Scenario: Quota exhaustion (402) → re-dispatch at lower tokens or fallback
- Scenario: Deterministic fallback activates when all AI fails
- Scenario: Verified BusinessProfile data unchanged after AI failure

### Task 4: Test Data Integrity
- File: `apps/api/test_data_integrity.js`
- Test: AI-generated phone cannot overwrite discovered phone
- Test: AI-generated name cannot overwrite identified name
- Test: AI-generated address cannot overwrite verified address
- Test: Failed AI enrichment preserves deterministic BusinessProfile
- Test: Grounding enforcement replaces unsupported claims with UNKNOWN
- Test: JSON repair preserves provenance as ai_generated with reduced confidence
- Test: Synthetic identity never enters canonical projection
- Test: Failed AI request doesn't corrupt previously extracted records
- Test: Provenance hierarchy enforced at every merge point
- Test: UNKNOWN envelope for missing/unsupported AI output

### Task 5: Test Cost Optimization
- File: `apps/api/test_cost_optimization.js`
- Test CostTracker records per-request and aggregates
- Test QuotaManager enforces monthly limits
- Test CapabilityRouter prefers free/cheaper models
- Test CacheManager caches deterministic results
- Test Per-task budgets enforced
- Test Runaway retries prevented by cost limits
- Test Free tier tracking and alerts
- Test Transition config flags work

### Task 6: Test Health Monitoring
- File: `apps/api/test_health_monitoring.js`
- Test `/health/ai` returns correct schema
- Test provider diagnostic endpoint
- Test health status transitions
- Test cooldown state reporting
- Test quota state reporting
- Test circuit breaker state reporting
- Test capability routing visibility
- Test no secrets in responses
- Test diagnostic endpoint rate limiting

### Task 7: Test Model Evaluation (from Plan 02-03)
- File: `apps/api/test_model_evaluation.js`
- Run evaluation harness against all testable models
- Verify metrics collection: correctness, hallucination, JSON validity, schema compliance
- Test UNTESTED models marked correctly
- Test comparison report generation

### Task 8: Test Circuit Breaker Behavior
- Unit tests for CircuitBreaker:
  - CLOSED → OPEN after failureThreshold
  - OPEN → HALF_OPEN after timeout
  - HALF_OPEN → CLOSED after successThreshold
  - HALF_OPEN → OPEN on failure
  - State persisted in Redis (mocked)
  - Concurrent access safety

### Task 9: Test Retry Controller
- Unit tests for RetryController:
  - Exponential backoff with jitter
  - Retry-After header respected
  - Max attempts enforced
  - Deadline respected (no retry past deadline)
  - Retryable vs non-retryable errors
  - Cost-aware retry limits

### Task 10: Test Fallback Controller
- Unit tests for FallbackController:
  - Fallback loop prevention (max depth)
  - Best provider selection (capability, health, cost, latency)
  - Cooldown providers not selected
  - OPEN circuit providers not selected
  - Fallback chain tracking

### Task 11: Test Cache Manager
- Unit tests for CacheManager:
  - Cache key generation (prompt + model + schema hash)
  - TTL expiration
  - Invalidation on model/schema/prompt change
  - Hit/miss tracking
  - Deterministic-only caching (no cache for temperature > 0)

### Task 12: Live Integration Tests (Conditional)
- File: `apps/api/test_live_integration.js`
- Only run when `AI_LIVE_TESTS=true` and credentials configured
- Test each provider with real API (1-2 requests each)
- Measure actual latency, cost, success rate
- Skip gracefully when credentials not configured
- Document in CI: "Live tests skipped - set AI_LIVE_TESTS=true and provide credentials to enable"
