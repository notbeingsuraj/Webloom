# Plan 02-07: Output Validation and Webloom Data Integrity

## Objective
Preserve Webloom's existing evidence and provenance architecture throughout the AI infrastructure.

**Critical Requirements:**
1. **AI cannot overwrite verified business information** - Provenance hierarchy: user_provided (5) > verified (4) > discovered (3) > identified (2) > inferred (1) > ai_generated (0.5). AI-generated (0.5) can NEVER overwrite identified (2) / discovered (3) / verified (4) / user_provided (5) for identity fields.
2. **AI-generated data must be labelled appropriately** - Every AI output carries provenance `ai_generated` with confidence and evidence snippet.
3. **Missing fields must remain missing** - Never manufacture missing information. UNKNOWN envelopes for unsupported claims.
4. **Unsupported information must not be fabricated** - Hallucination guard: evidence grounding enforcement.
5. **Source provenance must be preserved** - Every field tracks sourceId, evidenceId, extractionMethod.
6. **Failed AI requests must not corrupt previously extracted records** - Graceful degradation preserves deterministic data.
7. **Every structured output must be validated against its schema** - Schema validation before provenance attachment.
8. **Provider-specific response formats must be normalized** - Unified output shape regardless of provider.
9. **For models without native structured output support, implement reliable JSON extraction, parsing and schema validation** - Especially critical for Nemotron 3 Ultra.

### Task 5: Integrate OutputValidator with Provenance System
- File: `apps/api/src/ai/OutputValidator.js` (from Plan 02-06)
- After schema validation, attach provenance metadata to validated output
- For structured output: provenance = `ai_generated`, confidence from model, evidence = model's evidence snippet
- For JSON repair: provenance = `ai_generated`, confidence reduced, evidence = repair reasoning
- For deterministic extraction: provenance = `discovered` or `verified`

### Task 6: AIOrchestrator Provenance Attachment
- File: `apps/api/src/ai/AIOrchestrator.js` (from Plan 02-04)
- Every `execute()` result carries full provenance:

  - fallbackCount, attempts[] with per-attempt provenance
  - grounding report (checked, mode, grounded, unsupported, unverifiable)
  - confidence band from `overallConfidence()`
- Non-enumerable `__provenance` property on result (like existing `__ai`)

### Task 8: Implement Hallucination Guard for Evidence Grounding
- File: `apps/api/src/ai/grounding.js` (existing)

### Task 9: Implement UNKNOWN Envelope Pattern
- Standardize UNKNOWN representation for missing/unsupported AI output
- Schema: `{ value: null, confidence: null, evidence: null, provenance: 'ai_generated', unknownReason: 'unsupported'|'missing'|'hallucinated' }`
- Apply consistently across all AI-dependent services
- Frontend renders UNKNOWN as "Not available" not empty
