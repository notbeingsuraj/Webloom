<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → NewLead Form | Untrusted Google Maps URL input (validated client + server) |
| User → CSV Upload | Untrusted file content (parsing, validation, size limits) |
| Frontend → API | Authenticated agency user (session/JWT), but input validation required |
| API → External Providers | Geoapify, r.jina.ai, Google Maps (outbound, API keys secret) |
| API → AI Providers | OmniRoute (OpenAI, Anthropic, etc.) — prompts contain business data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | Google Maps URL input | mitigate | Client + server validation (BusinessDataExtractor.validateGoogleMapsUrl), allowlist hosts |
| T-01-02 | Tampering | CSV upload content | mitigate | Parse with csv-parse, validate each row, size limit 1MB, row limit 500 |
| T-01-03 | Repudiation | Lead creation | mitigate | Audit log in lead persistence (createdAt, updatedAt, userId) |
| T-01-04 | Info Disclosure | Business data in prompts | mitigate | AIService safe logging (secret redaction), no PII in prompts beyond business info |
| T-01-05 | DoS | Analysis pipeline (long-running) | mitigate | REQUEST_TIMEOUT_MS=300s, axios timeout, queue/rate limit per user |
| T-01-06 | Elevation | Report sharing links | mitigate | Unguessable tokens, optional expiry, access logging |
| T-01-07 | Injection | Prompt injection from website content | mitigate | BusinessDataExtractor sanitizes HTML, prompt templates use structured evidence not raw text |
| T-01-08 | SSRF | Official website fetch | mitigate | OfficialWebsiteProvider validates URL scheme/host, blocks private IPs, timeout |
</threat_model>
