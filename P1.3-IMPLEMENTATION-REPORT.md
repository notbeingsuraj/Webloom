## 3. CanonicalBusinessProfile Contract

Implemented in `apps/api/src/services/CanonicalBusinessProfileService.js`
(singleton default export `CanonicalBusinessProfileService`, named export `PROVENANCE_PRIORITY`).

```js
{
  identity: {
    entityId,            // persisted entity id (ent_*) only; NEVER a provider id
    name,                // authoritative name; null when absent (never synthetic)
    address,             // full address string
    addressComponents: { street, city, state, country, postalCode },
    phone,
    website,
    domain,              // hostname derived from website
    coordinates,         // { lat, lng } object; null when absent
  },
  business: {
    category, categories[], description, businessType,
    services[], products[], amenities[], hours, email,
    socialLinks[], pricing, bookingUrl,
  },
  reputation: { rating, reviewCount, reviews[] },
  providers: [            // provider metadata — NEVER identity
    { provider, providerRecordId, resolutionMethod, resolutionConfidence, firstSeen, lastSeen },
  ],
  provenance: {           // field-level, only where the source carries it
    '<fieldPath>': { provenance, confidence, source, updatedAt },
  },
  confidence: { entity, '<fieldPath>' }, // only where present in source
  enrichment: { aiExtracted, aiGeneratedFields, acquisitionMethod, providerUnavailable },
}
```

Missing values use `null` for scalars and `[]` for arrays — the repository
convention (matches `BusinessProfile.get()` and the flat provider shapes).
`undefined` is never emitted as a missing marker.

**APIs (spec §2):**

- `fromBusinessProfile(profile)` — accepts a `BusinessProfile` instance, its
  `.data` map, a flattened `toObject()` map, or any plain provider/intelligence
  object. Synchronous, pure.
- `fromEntityData({ entity?, record?, canonicalFields?, providerIdentities? })`
  — projects a provider record + optional persisted canonical fields /
  provider identities. Synchronous, pure.
- `fromPersistedEntity(entityIdOrRepo, repo?)` — accepts
  `fromPersistedEntity(repo, entityId)` **or** `fromPersistedEntity(entityId, repo)`
  for convenience, plus a pre-loaded entity object. **Read-only** —
  uses repository `getEntityById` / `getCanonicalFields` / `getObservations`,
  plus a read-only `provider_identity` query via the repository's own drizzle
  instance when `findProviderIdentities` doesn't exist.

## 4. Read-Layer Architecture

```
               ┌────────────────────────────────────────────────┐
               │  CanonicalBusinessProfileService (the ONE layer) │
               └────────────────────────────────────────────────┘
   fromBusinessProfile ──► fromEntityData ──► canonical projection
   fromEntityData  ─────► { record, canonicalFields, providerIdentities }
   fromPersistedEntity ─► repo reads → _projectLoadedEntity → canonical projection
```

Projection flow (deterministic, no side effects):

1. **Source shape detection** — each canonical field has an ordered list of
   reader functions that consume *all four* repository shapes:
   flat provider (`business.name`), BusinessProfile data
   (`identity.name.{value,provenance}`), intelligence
   (`identity.name` / `contact.phone` / `location.address` / `rating` /
   `reviewCount` / `openingHours`), legacy bare field (`name`), and
   data-wrapped shapes (`data.identity.name`). The first non-null read wins.
2. **Unwrapping** — `{ value, provenance, confidence }` field objects are
   deterministically unwrapped to `value` while provenance/confidence are
   carried to the `provenance`/`confidence` sections.
3. **Guards** — synthetic-name filter + provider-id isolation + AI provenance
   preservation run at projection time (see §5, §6, §7).
4. **Persisted override** — when `canonicalFields` are supplied, persisted
   canonical values are authoritative over provider-record values
   (applied via `_applyCanonicalFields`).
5. **Read-only assembly** — `fromPersistedEntity` performs DB **reads** only;
   it never creates/updates entities, canonical fields, observations, or
   provider identities, and never resolves entities as a side effect.

Projection consumes existing normalized/canonical values where they exist.
This layer does **not** re-normalize phone/domain/address (that stays in
`FieldNormalizer` / `EntityResolution`), and never persists its output.

## 5. Identity Safety

Synthetic identity is impossible at the canonical boundary:

- `canonicalName()` returns `null` when no authoritative name exists, and the
  regex `^(unknown\s*business|unknown|n\/a|na|unnamed\s*business|unnamed)$`
  strips any synthetic placeholder that a source may contain.
- The projection never produces `"Unknown Business"`, `"Unknown"`, `"N/A"`,
  or `"Unnamed Business"` — tests B7–B10 lock this in.
- Provider IDs (`placeId`, `providerRecordId`, `cid`) can never become
  `identity.name` / `identity.address` / `identity.phone` / `identity.website`
  because they are only ever read into the `providers[]` section (tests B11/B12,
  D1–D3).
- `entityId` is accepted only when it is an authoritative
  `ent_`-prefixed persisted id or an explicit `entityId` on the record —
  never a provider id (test B12).

## 6. AI Provenance Safety

`ai_generated` provenance survives projection untouched:

- `fromBusinessProfile` on a `BusinessProfile` instance reads provenance via
  `getField(path)` and the extraction history (`data.metadata.extractionHistory`),
  so an `ai_generated` field is recorded under `provenance['<fieldPath>'].provenance === 'ai_generated'` — never upgraded to
  `verified`/`discovered`/`identified`/`user_provided`/`authoritative` (tests C3/C4, P5, L2).
- `metadata.aiExtracted` (the P1.2 quarantine flag emitted by
  `BusinessDataExtractor` and consumed by `BusinessResearchService._mergeCanonical`)
  is surfaced under `enrichment.aiExtracted` so consumers can see AI-derived
  records without them masquerading as verified identity (tests C1/C2).
- Persisted canonical fields with `ai_generated` provenance round-trip
  unchanged through `fromPersistedEntity` (tests P5, L2).

**Regression test proving no provenance upgrade:**
AI-generated input → `fromBusinessProfile` → `provenance['identity.description'].provenance === 'ai_generated'`
(tests C3, C4) and persisted AI field → `fromPersistedEntity` → still `ai_generated` (P5, L2).

## 7. Provider Isolation

Provider metadata is never flattened into identity:

- `providers[]` entries carry `{ provider, providerRecordId, resolutionMethod,
  resolutionConfidence, firstSeen, lastSeen }`.
- Sources: the flat `provider: { name, placeId, datasource }` object (Geoapify
  adapter), `source: { provider, url, ... }` (web-extraction), a provider-name
  string with `placeId`, and persisted `provider_identity` rows.
- Two providers may resolve to the same canonical entity while keeping
  distinct provider IDs. `fromEntityData` merges persisted provider rows with
  record-level provider metadata, deduped on `(provider, providerRecordId)`.
- Tests D1–D5 assert Google and Geoapify IDs stay in `providers[]` and that
  removing provider metadata does not change canonical business meaning.

## 13. Known Limitations

1. **Hours normalization** — `normalizeHoursShape()` best-effort delegates to
   `FieldNormalizer` for string forms but keeps a side-effect-free fallback.
   Since the provider boundary (`ProviderAdapter.normalizeHours`) already
   normalizes provider hours once, the projection usually receives already
   canonical day maps. Deep hour-string normalization via
   `FieldNormalizer.normalizeHours` inside the projection is intentionally
   avoided to keep the projection pure/synchronous.
2. **`city/state/country/postalCode`** live under
   `identity.addressComponents` (not top-level) — a deliberate contract choice
   to keep `identity` compact; consumers use `.addressComponents`.
3. **`fromPersistedEntity` provider-identity read** — when a repository lacks
   `findProviderIdentities`, the service performs a read-only drizzle query
   against `provider_identity` via the repository's own `db`. If the repo has
   no `db` handle, `providers[]` is simply empty (never fabricated).
4. **AI-extracted record provenance** — for a bare record (no
   `BusinessProfile`/canonical fields) with `metadata.aiExtracted`, the
   projection surfaces `enrichment.aiExtracted` but cannot attach per-field
   `ai_generated` provenance (the record carries none). BusinessProfile /
   persisted inputs with `ai_generated` provenance preserve it exactly.
5. **No aggregate npm test script** — `package.json` `test` runs only
   `test_providers.js`; the full regression is a manual sequence. This is
   pre-existing, not introduced here.
